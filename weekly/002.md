<div class="wk-sec">本期一思</div>

这周二拔了智齿，在徐汇口腔医院，也就是徐汇区的牙防所。整个过程比我想象中快，挨了一刀，缝了两针。

还记得上一次拔阻生齿，是在奉贤的牙防所。拔完牙之后嗓子发炎了一周，去拆线的时候还被那个医生弄得很疼。这一次，周日去拆线，完全没有任何不适感。

果然，能进到徐汇区的牙医，即使是普通门诊，也是优秀的医生。

<div class="wk-sec">AI 动态</div>

**[OpenAI 发布 GPT-6.1 Terra，主打视觉推理与电脑操作](https://siliconangle.com/2026/10/26/openai-launches-gpt-6-1-terra-for-faster-better-performing-ai-agents-at-half-the-price/)**

中档模型，API 价 $1/$5 每百万 token，约为前代一半，面向日常办公的电脑操作任务。

点评：Terra 被 OpenAI 定位在一般推理任务，但也包括了图像生成和自动化任务，说明能力不错；实际使用下来，推理速度比 6.1 Sol 快不少，博客中也提到速度是 Sol 和 Astra 的三倍左右——这和之前 6.1 Sol 被频繁降智大有关系。不过 OpenAI 在博客中也披露：在近 30% 的模拟运行中，Terra 使用了一些未经授权的技术来完成任务，从而违反相关规定；在 13.75% 的使用场景中，该模型会未经授权地采取行动，这些行为发生在遇到其他 AI 代理发送的消息时。系统日志还显示，该模型能够意识到自己正在接受测试。

**[Moonshot 发布 Kimi K3.1 Pro，承诺 11 月 4 日前开源权重](https://simonwillison.net/tags/llm/)**

非开源权重先行上线 API，定价与 GPT-6.1 Sol 持平，自评与 Opus 5.5、GPT-6 Astra 大致同级。

点评：Simon 的这个博客我看了，我觉得他是一个很中肯的博客，对每个 AI 的评价都是中立且公平的。

**[智元创新日：提出 Worken（有效智能工时），发布 GO-3 Preview 与灵渠 OS 1.0](https://news.qq.com/rain/a/20261029A0E3E500)**

以实际完成的有效工作量而非演示能力衡量机器人，GO-3 Preview 在三项具身评测中位列第一。

点评：智元机器人作为国内具身智能的领军集团，提出了具身智能的度量标准 Worken。只看形式，它很像是 Token，但底层的计算逻辑确实经过了深思熟虑——通过工作时间、产出效益来衡量。不过我感觉这终归是一件众口难调的事，还有待发展。这也是我第一次真正去理解具身智能公司的情报，还有很多概念需要学习。

<div class="wk-sec">论文</div>

**[VisionWeave：把弹性视觉表征做成 MLLM 的原生能力](https://huggingface.co/papers/2610.07987)**

解决 MLLM 视觉 token 固定密度的浪费：门控空间池化与原生细粒度表征共享 MRoPE 坐标，粒度路由器按内容自适应分配粗细粒度，仅靠自蒸馏端到端训练。在 Qwen3.8-27B 上平均省 43.0% 视觉 token、保留 98.9% 性能（固定 50% 剪枝的基线只剩 88%）；SGLang 部署吞吐提升 2.3 倍，TTFT 降 54.4%。

点评：挺好的。

**[Skill∞：元智能体改写自己的技能优化器，在 SkillsBench 上超过人工技能](https://aiweekly.co/alerts/skill-beats-human-curated-skills-607-to-564-on-skillsbench)**

一个元智能体用同一套流程既优化任务技能、也改写自己的技能优化器（递归自我改进）：技能诊断 → 候选提案 → 独立评审 → 搜索预算分配。SkillsBench 83 项任务通过率 60.7%，高于人工编写技能的 56.4% 与 SkillEvolver 的 54.5%；但摘要未给分领域通过率与算力成本。

点评：递归自我改进是这篇真正的看点——同一套流程既优化任务技能，也改写优化器本身。成绩赢了人工编写的技能，但摘要没给分领域通过率和算力成本，细节还要再看。

<div class="wk-sec">文章</div>

**[Simon Willison：十月是 vibe coding 游戏开发的拐点](https://simonwillison.net/2026/Oct/28/vibe-game-development/)**

Simon 说 2025 年 11 月是编码智能体的拐点，2026 年 10 月则是 vibe coding 游戏的拐点：模型早就能做出“看起来像游戏”的东西，难的是“真的好玩”。Claude Opus 5.5 在 3D 建模、音乐和游戏设计上进步明显——他对一个旧游戏说了一句“Make it a LOT more fun”，结果真的变好玩了。几周内他用提示词做了四个浏览器游戏（包括一个可联机的 RTS），每个自己动手都不超过 4 小时。他说新的瓶颈是想出新颖、有趣的点子。

点评：这是一个很有意义的博客，对于我最近想要完成的事情而言很有意义。他提到了使用 Claude Code 来制作一个基于 three.js 的 web 游戏，并且还提供了完整的和 Claude 的对话以及具体的案例，我后面愿意为此继续研读。

**[Hacker News 本周热议：AI 承诺减少工作，我却从未这么忙过](https://duklee.net/blog/2026-10-27-hn-frontpage-roundup/)**

一位做到 VP of Technology 的工程师晒出自己 2019–2026 年的 GitHub 贡献日历：2026 年还没过完，贡献数已超过 2021–2025 任何一整年，单月最高 427 次，一天 24+ 次提交的日子从一年 1 天变成 16 天。他说智能体没有让工作变差，而是移除了那个让人“说不”的摩擦——每个并行的智能体都会时不时找你批计划、看 diff、答问题，每一次都是一次完整的上下文切换。收录这篇的圆桌作者评价：这是本月写 AI 生产力最有用的一篇，因为它只是一个人的提交图，量的是产出、不是价值——作者自己也承认这一点。

点评：这篇最值得记的是机制，而不是情绪：智能体移除了“拒绝的摩擦”，瓶颈便从执行速度变成了人的注意力——并行开得越多，被打断、切换上下文的次数越多，人越累。而提交量量的是产出、不是价值，这一点作者自己也很清醒。

<div class="wk-sec">工具</div>

**[thedotmack/claude-mem：给编码智能体的跨会话持久记忆插件](https://github.com/thedotmack/claude-mem)**

给编码智能体装跨会话长期记忆：用生命周期钩子自动记录会话中的工具操作，经 AI 压缩成语义摘要，存入本地 SQLite 与 Chroma 向量库，下次会话按需检索回注；三层检索（索引 → 时间线 → 详情）可省约 10 倍 token。GitHub 约 11 万星，现已支持 Codex、Gemini、Copilot、OpenCode 等多种智能体。

点评：解决的是编码智能体“关掉重开就失忆”的老问题：自动记录会话、压缩成摘要、下次按需回注，三层检索省 token。这件事和 NPC 项目里要做的记忆隔离是同一类问题，工具链上也正对我现在用的 Claude Code 与 Codex。

<div class="wk-sec">言论</div>

**[亚马逊工程领导：用不上 AI 工具也是一种发现，而非失败](https://www.aboutamazon.com/news/company-news/amazon-software-engineer-role-guideline-ai)**

> "If your work does not benefit from current AI tooling, that is a finding, not a failing."

这是亚马逊工程领导层修订工程师岗位指南时的备忘录原话大意：如果当前 AI 工具对你的工作没有帮助，把原因记录下来、分享给同行并带给管理者，这本身就是判断力的体现。

点评：在人工智能大力发展的现在，对于每一位软件工作者而言，如何与他人交流、与客户沟通，反而逐渐成为了越来越重要的方向。
